১. Client-Side Rendering (CSR)সাধারণ React অ্যাপ্লিকেশন যেভাবে কাজ করে, এটিও ঠিক সেভাবেই কাজ করে।
কীভাবে কাজ করে: ব্রাউজার প্রথমে একটি প্রায় ফাঁকা HTML ফাইল এবং কিছু জাভাস্ক্রিপ্ট বান্ডিল ডাউনলোড করে। এরপর ব্রাউজারের ভেতরেই (Client-side) জাভাস্ক্রিপ্ট রান করে ডাটা ফেচ করে এবং UI তৈরি করে।   
সুবিধা: একবার লোড হয়ে গেলে পেজ ট্রানজিশন খুব দ্রুত হয়।অসুবিধা: প্রাথমিক লোডিং টাইম (Initial load) বেশি লাগে এবং SEO-এর জন্য এটি খুব একটা ভালো নয়, কারণ সার্চ ইঞ্জিন ক্রলাররা প্রথমে কোনো কন্টেন্ট দেখতে পায় না।   কখন ব্যবহার করবেন: ড্যাশবোর্ড, ইউজার প্রোফাইল বা এমন পেজ যেখানে প্রচুর ইউজার ইন্টারঅ্যাকশন আছে কিন্তু SEO গুরুত্বপূর্ণ নয়।   ব্যবহার: useEffect হুক, useSWR বা React Query ব্যবহার করে ডাটা ফেচিং।   

২. Server-Side Rendering (SSR)SSR-এ প্রতিটি রিকোয়েস্টের জন্য সার্ভার রিয়েল-টাইমে পেজ রেন্ডার করে।কীভাবে কাজ করে: ব্যবহারকারী যখন কোনো পেজে ভিজিট করে, তখন সার্ভার ডাটাবেস বা API থেকে ডাটা নিয়ে পুরো HTML পেজ তৈরি করে ব্রাউজারে পাঠায়।   সুবিধা: ব্যবহারকারী সবসময় লেটেস্ট বা আপডেটেড ডাটা দেখতে পান। সম্পূর্ণ HTML রেন্ডার হয়ে আসে বলে এটি SEO-এর জন্য চমৎকার।   অসুবিধা: প্রতিটি রিকোয়েস্টে সার্ভারকে কাজ করতে হয় বলে এটি তুলনামূলকভাবে একটু ধীর গতির হতে পারে।কখন ব্যবহার করবেন: নিউজ পোর্টাল, ই-কমার্স সাইটের প্রোডাক্ট পেজ বা এমন পেজ যার ডাটা প্রতিনিয়ত পরিবর্তন হয়।   ব্যবহার (Pages Router): getServerSideProps ফাংশন ব্যবহার করে।  

 ৩. Static Site Generation (SSG)Next.js-এ পারফরম্যান্সের দিক থেকে এটি সবচেয়ে সেরা মেথড।কীভাবে কাজ করে: প্রজেক্ট যখন প্রোডাকশনের জন্য বিল্ড (Build) করা হয়, তখনই সার্ভার ডাটা ফেচ করে HTML পেজগুলো তৈরি করে ফেলে। এরপর যতোবারই ইউজার রিকোয়েস্ট পাঠাক না কেন, আগে থেকে তৈরি করা সেই স্ট্যাটিক HTML ফাইলটি সরাসরি CDN থেকে সার্ভ করা হয়।   সুবিধা: এটি অত্যন্ত দ্রুত গতির এবং SEO-এর জন্য সেরা।   অসুবিধা: ডাটা পরিবর্তন হলে তা সাথে সাথে ওয়েবসাইটে আপডেট হয় না। নতুন ডাটা দেখতে হলে পুরো প্রজেক্টটি আবার রি-বিল্ড করতে হয়।কখন ব্যবহার করবেন: ব্লগ পোস্ট, পোর্টফোলিও, ডকুমেন্টেশন বা মার্কেটিং পেজ—যেখানে ডাটা খুব ঘনঘন পরিবর্তন হয় না।   ব্যবহার (Pages Router): getStaticProps ফাংশন ব্যবহার করে।   
 
 ৪. Incremental Static Regeneration (ISR)এটি মূলত SSG-এর একটি উন্নত ও মডার্ন রূপ।কীভাবে কাজ করে: এটি SSG-এর মতোই বিল্ড টাইমে পেজ তৈরি করে, কিন্তু এতে আপনি একটি নির্দিষ্ট সময় (যেমন- ৬০ সেকেন্ড) সেট করে দিতে পারেন। ওই সময় পার হওয়ার পর কেউ পেজটিতে ভিজিট করলে, Next.js ব্যাকগ্রাউন্ডে নতুন ডাটা দিয়ে পেজটি রি-বিল্ড করে নেয়।   সুবিধা: পুরো ওয়েবসাইট রি-বিল্ড না করেই স্ট্যাটিক পেজের ডাটা আপডেট করা যায়।কখন ব্যবহার করবেন: বড় ই-কমার্স সাইট বা ব্লগ যেখানে প্রচুর পেজ আছে এবং ডাটা মাঝে মাঝে আপডেট হয়।ব্যবহার: getStaticProps এর ভেতর revalidate প্রপার্টি রিটার্ন করে।   
 
 ৫. React Server Components (RSC) — (Next.js 13+ App Router)Next.js এর নতুন App Router-এ (Next.js ১৩, ১৪, ১৫) রেন্ডারিং মেকানিজমকে আরও উন্নত করা হয়েছে।   Server Components (Default): App Router-এ ডিফল্টভাবে সব কম্পোনেন্টই সার্ভার কম্পোনেন্ট। এগুলো শুধু সার্ভারেই রেন্ডার হয় এবং ক্লায়েন্টে কোনো জাভাস্ক্রিপ্ট কোড পাঠায় না। ফলে বান্ডিল সাইজ অনেক ছোট হয় এবং পেজ দ্রুত লোড হয়। সার্ভার কম্পোনেন্ট থেকে সরাসরি ডাটাবেস কুয়েরি করা যায়।   Client Components: যদি আপনার কম্পোনেন্টে ইউজার ইন্টারঅ্যাকশন (যেমন- onClick ইভেন্ট) বা স্টেট (useState, useEffect) ব্যবহার করার প্রয়োজন হয়, তবে ফাইলের সবার উপরে 'use client' লিখে সেটিকে ক্লায়েন্ট কম্পোনেন্ট বানাতে হয়।   সংক্ষেপে বলতে গেলে: Next.js আপনাকে সুযোগ দেয় একটি পেইজকে SSG দিয়ে সুপার ফাস্ট করতে, অন্য একটি পেইজকে SSR দিয়ে রিয়েল-টাইম রাখতে, এবং ড্যাশবোর্ডকে CSR দিয়ে ইন্টারঅ্যাকটিভ করতে। আপনার প্রজেক্টের রিকোয়ারমেন্ট অনুযায়ী সঠিক মেথডটি বেছে নেওয়াই হলো একজন ভালো ডেভেলপারের কাজ।
