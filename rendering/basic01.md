রেন্ডারিং (Rendering) বলতে বোঝায় আপনার লেখা React বা JavaScript কোডগুলো কীভাবে HTML-এ রূপান্তরিত হয়ে ইউজারের ব্রাউজারে প্রদর্শিত হবে।   Next.js-এর সবচেয়ে বড় শক্তি হলো এর রেন্ডারিং আর্কিটেকচার। বেসিক থেকে অ্যাডভান্সড লেভেল পর্যন্ত Next.js-এর রেন্ডারিং মেকানিজমগুলো নিচে বিস্তারিতভাবে আলোচনা করা হলো:
১. Client-Side Rendering (CSR) - [The Basic React Way]সাধারণ React অ্যাপ্লিকেশন (যেমন create-react-app) মূলত CSR ব্যবহার করে কাজ করে।   কীভাবে কাজ করে: ইউজার যখন ওয়েবসাইটের রিকোয়েস্ট দেয়, তখন সার্ভার থেকে একটি প্রায় ফাঁকা HTML ফাইল এবং একটি বড় JavaScript ফাইল (বান্ডিল) ব্রাউজারে আসে। এরপর ব্রাউজার সেই JS ফাইল রান করে পেজের কন্টেন্ট ও UI তৈরি করে।   ডিপ ডাইভ: পেজ প্রাথমিকভাবে লোড হওয়ার পর ডাটা ফেচিং (useEffect বা React Query দিয়ে) ব্রাউজার থেকেই হয়।   সুবিধা: একবার স্ক্রিপ্ট লোড হয়ে গেলে পেজগুলো সিঙ্গেল পেজ অ্যাপ্লিকেশনের (SPA) মতো খুব দ্রুত কাজ করে।অসুবিধা: Initial Load Time (প্রথমবার লোড হতে) অনেক বেশি সময় লাগে। সার্চ ইঞ্জিন (Google Bot) ক্রল করার সময় প্রথমে কোনো কন্টেন্ট দেখতে পায় না, তাই SEO-এর জন্য এটি মোটেও ভালো নয়।কখন ব্যবহার করবেন: এডমিন ড্যাশবোর্ড, ইউজার প্রোফাইল বা এমন ওয়েব অ্যাপ যেখানে প্রচুর ইউজার ইন্টারঅ্যাকশন আছে কিন্তু SEO গুরুত্বপূর্ণ নয়।

২. Server-Side Rendering (SSR) - [Dynamic Server HTML]SSR হলো রিয়েল-টাইম রেন্ডারিং, যা প্রতিটি রিকোয়েস্টের জন্য নতুন করে পেজ তৈরি করে।   কীভাবে কাজ করে: ইউজার যখন কোনো পেজে ভিজিট করে, রিকোয়েস্টটি সরাসরি সার্ভারে যায়। সার্ভার সাথে সাথে ডাটাবেস বা API থেকে ফ্রেশ ডাটা নিয়ে পুরো HTML ফাইলটি তৈরি করে ইউজারের ব্রাউজারে পাঠায়।   ডিপ ডাইভ: ব্রাউজার সম্পূর্ণ HTML পাওয়ার পর ইউজার সাথে সাথেই কন্টেন্ট দেখতে পায়। এরপর Next.js এর সাথে জাভাস্ক্রিপ্ট যুক্ত করে পেজটিকে ক্লিকেবল বা ইন্টারেক্টিভ করে তোলে। এই প্রক্রিয়াকে বলা হয় Hydration।   সুবিধা: ইউজার সবসময় আপডেটেড ডাটা পায়। পুরো HTML সার্ভার থেকে আসে বলে এটি SEO-এর জন্য চমৎকার।   অসুবিধা: প্রতিটা রিকোয়েস্টে সার্ভারকে নতুন করে প্রসেস করতে হয়, তাই সার্ভারের ওপর চাপ পড়ে এবং রেসপন্স টাইম কিছুটা বেশি হতে পারে।   কখন ব্যবহার করবেন: ই-কমার্স সাইটের চেকআউট পেজ, পার্সোনালাইজড সার্চ রেজাল্ট বা এমন পেজ যার ডাটা প্রতিনিয়ত পরিবর্তন হয়।   

৩. Static Site Generation (SSG) - [Build Time HTML]পারফরম্যান্স এবং স্পিডের দিক থেকে এটি Next.js-এর সবচেয়ে সেরা রেন্ডারিং মেথড।   কীভাবে কাজ করে: আপনি যখন প্রোডাকশনের জন্য প্রজেক্ট বিল্ড (npm run build) করেন, তখনই সার্ভার ডাটা ফেচ করে সব পেজের HTML ফাইল তৈরি করে ফেলে।ডিপ ডাইভ: বিল্ড হওয়ার পর পেজগুলো CDN (Content Delivery Network)-এ সেভ করা থাকে। এরপর লাখ লাখ ইউজার রিকোয়েস্ট করলেও কোনো সার্ভার প্রসেসিং বা ডাটাবেস হিট হয় না; সরাসরি CDN থেকে আগে থেকে তৈরি করা HTML ফাইল সার্ভ হয়।   সুবিধা: চরম মাত্রায় ফাস্ট এবং SEO-এর জন্য সেরা। সার্ভার কস্ট প্রায় শূন্য।   অসুবিধা: ডাটা আপডেট করলে ইউজার সাথে সাথে তা দেখতে পায় না। নতুন ডাটা দেখাতে হলে পুরো প্রজেক্ট আবার রি-বিল্ড করতে হয়।   কখন ব্যবহার করবেন: ব্লগ পোস্ট, পোর্টফোলিও, ডকুমেন্টেশন, মার্কেটিং ল্যান্ডিং পেজ—যেখানে ডাটা ঘনঘন পরিবর্তন হয় না।   

৪. Incremental Static Regeneration (ISR) - [SSG with a Timer]SSG-এর ডাটা আপডেট না হওয়ার সীমাবদ্ধতা দূর করতেই ISR-এর জন্ম।   কীভাবে কাজ করে: এটি মূলত SSG-এর মতোই কাজ করে, কিন্তু এতে আপনি একটি Revalidation Time (যেমন: ৬০ সেকেন্ড) সেট করে দিতে পারেন।   ডিপ ডাইভ: ৬০ সেকেন্ড পার হওয়ার পর প্রথম যে ইউজার পেজটিতে ভিজিট করবে, সে তাৎক্ষণিকভাবে আগের পুরনো পেজটিই দেখবে। কিন্তু ব্যাকগ্রাউন্ডে Next.js নতুন ডাটা ফেচ করে পেজটিকে পুনরায় বিল্ড (Regenerate) করে ফেলবে। এরপর থেকে বাকি সব ইউজার আপডেটেড পেজটি দেখতে পাবে।   সুবিধা: সম্পূর্ণ ওয়েবসাইট রি-বিল্ড করার ঝামেলা ছাড়াই স্ট্যাটিক পেজের ডাটা ফ্রেশ রাখা যায়।   কখন ব্যবহার করবেন: বড় ই-কমার্স সাইটের প্রোডাক্ট ক্যাটালগ বা নিউজ পোর্টাল—যেখানে প্রচুর পেজ আছে এবং ডাটা মাঝে মাঝে আপডেট হয়।  

 ৫. React Server Components (RSC) - [Advanced Architecture]Next.js 13+ App Router আসার পর রেন্ডারিং আর্কিটেকচারে একটি বৈপ্লবিক পরিবর্তন আসে।   সার্ভার কম্পোনেন্ট (RSC): App Router-এ ডিফল্টভাবে সব কম্পোনেন্টই সার্ভার কম্পোনেন্ট। এগুলো শুধুমাত্র সার্ভারেই এক্সিকিউট হয় এবং ব্রাউজারে কোনো JavaScript বান্ডিল পাঠায় না। ফলে পেজ সাইজ অনেক ছোট হয়। আপনি সরাসরি এই কম্পোনেন্ট থেকে ডাটাবেস কুয়েরি করতে পারবেন।   ক্লায়েন্ট কম্পোনেন্ট: যদি আপনার কম্পোনেন্টে ইউজার ইন্টারঅ্যাকশন (যেমন- onClick ইভেন্ট) বা স্টেট (useState, useEffect) প্রয়োজন হয়, তখন ফাইলের একদম শুরুতে 'use client' লিখে সেটিকে ক্লায়েন্ট কম্পোনেন্ট বানাতে হয়।Key insight: RSC-এর সবচেয়ে বড় ম্যাজিক হলো, সার্ভার ও ক্লায়েন্ট কম্পোনেন্টকে একসাথে মিশিয়ে ব্যবহার করা যায়। ভারী ডাটা ফেচিংয়ের কাজ সার্ভার করে, আর শুধুমাত্র ইন্টারঅ্যাকটিভ অংশগুলোর জাভাস্ক্রিপ্ট ইউজারের ব্রাউজারে আসে।
 
 ৬. Partial Prerendering (PPR) - [The Future]PPR হলো Next.js-এর একটি সর্বাধুনিক ও এক্সপেরিমেন্টাল ফিচার, যা SSG এবং SSR-এর মধ্যে সীমানা মুছে দিচ্ছে।   কীভাবে কাজ করে: এটি একটি সিঙ্গেল পেজের ভেতরে স্ট্যাটিক এবং ডায়নামিক রেন্ডারিং-কে একসাথে যুক্ত করে।   ডিপ ডাইভ: ধরুন একটি ই-কমার্স প্রোডাক্ট পেজ। এর হেডার, ফুটার এবং প্রোডাক্টের ছবি স্ট্যাটিক (SSG) হিসেবে সাথে সাথে লোড হয়ে যাবে। কিন্তু একই পেজের "লাইভ স্টক চেক" বা "কার্ট আইটেম" অংশটি ডায়নামিক (SSR) হিসেবে সার্ভার থেকে ব্যাকগ্রাউন্ডে স্ট্রিম (Stream) হয়ে আসবে।এর ফলে ইউজারকে ফাঁকা স্ক্রিন দেখতে হয় না, স্ট্যাটিক অংশ সাথে সাথেই রেন্ডার হয়ে যায়।   রেন্ডারিং স্ট্র্যাটেজিকখন তৈরি হয়?SEO পারফরম্যান্সসর্বোত্তম ব্যবহারCSRইউজারের ব্রাউজারেদুর্বলপ্রাইভেট ড্যাশবোর্ড, সিঙ্গেল পেজ অ্যাপ্লিকেশনSSRপ্রতিটি রিকোয়েস্টের সময়অসাধারণশপিং কার্ট, পার্সোনালাইজড পেজ, ডায়নামিক সার্চSSGপ্রোডাকশন বিল্ড টাইমেসেরাব্লগ, ডকুমেন্টেশন, স্ট্যাটিক মার্কেটিং পেজISRবিল্ড টাইমে + নির্দিষ্ট সময় পরপরসেরাপ্রোডাক্ট পেজ, বিশাল সাইট যেখানে বিল্ড টাইম কমানো জরুরিPPR (নতুন)স্ট্যাটিক অংশ বিল্ড টাইমে, ডায়নামিক রিকোয়েস্টেসেরামডার্ন ওয়েব অ্যাপ যেখানে স্ট্যাটিক ও ডায়নামিক ডাটা একসাথে থাকেNext.js-এর মূল সৌন্দর্য হলো আপনাকে পুরো প্রজেক্টের জন্য একটি নির্দিষ্ট মেথডে আটকে থাকতে হবে না। আপনি চাইলে আপনার ব্লগের জন্য SSG, প্রোডাক্ট পেজের জন্য ISR এবং ইউজারের ড্যাশবোর্ডের জন্য CSR একসাথে একই অ্যাপ্লিকেশনে ব্যবহার করতে পারবেন।
